# Agent Note: 会话提问导航

Status: implemented

[English](2026-08-28-question-navigation.md) | 中文

## 问题

长会话要反复手动滚动才能回到用户的提问，而转录区的分页历史意味着「只索引可见部分」会漏掉更早的提问。

## 决策

Chat 视图从已定稿的 `user` Chat Node 推导出一份提问索引，并把导航的呈现限制在会话插件内部。一组粘性控件与回到底部按钮共用既有的、基于输入框高度的锚点。它暴露相邻跳转、当前提问的紧凑标记，以及一份可搜索的完整列表。

当前提问是位于转录区阅读边缘或其上方的最后一条用户行。跳转会把目标行对齐到顶部，尊重「减少动态效果」偏好，并施加两秒的视觉高亮。若要移动到已加载头部之前，会先请求上一页更早的历史再定位目标；打开完整列表时，继续复用既有的历史分页操作，而不是引入第二条会话数据通路。

提问导航快捷键使用会话设置命名空间。平台默认值在 macOS 上是 Command 加方向键，其他平台是 Control。「通用」设置里的这一行可以录制任意非修饰键，对不带修饰键的单键要求显式确认，拒绝只按修饰键，阻止上一个/下一个绑定重复，并提供三种触发范围策略。默认策略在表单控件与可编辑区域内不触发快捷键。

## 验证

运行 ui-conversation 的 TypeScript 构建、Chat 视图的定向组件测试套件、Web 前端构建，以及针对另行启动的 `dsh web` 实例的浏览器冒烟测试。

## 曾考虑的替代方案

**只索引已渲染的行** — 否决，因为转录区的历史是分页的，用当前已挂载的内容建索引会悄悄漏掉最早的提问。这正是本特性要消除的那个失败，而且只要会话超过一页它就会重新出现。

**用独立的会话查询加载完整提问列表** — 否决，因为那会在既有的 `loadOlder` 分页旁边再立一条数据通路。展开列表改为复用该操作，于是回放、分页与索引保持同一个权威来源。

**给这组控件单独的视口锚点** — 否决，因为第二个独立锚点会随输入框增高或换行而与之错位。共用回到底部按钮那个基于输入框高度的锚点，可让两个控件遵循同一条定位规则。

**把快捷键绑定放在每个会话的导航控件上** — 否决，因为按键绑定属于全局交互偏好，而非按会话的状态。把它留在会话设置命名空间里，一次绑定即对所有会话生效，录制入口也得以留在「通用」设置中、与其他输入偏好并列。

## 后果

该特性不新增会话事件，也不改变模型可见的历史。它只依赖 Chat Node 投影与既有的 `loadOlder` 操作，因此回放与分页保持同一个权威来源。紧凑索引刻意最多显示邻近的七条；展开后的列表仍是完整的已加载索引，并包含本地文本过滤。
