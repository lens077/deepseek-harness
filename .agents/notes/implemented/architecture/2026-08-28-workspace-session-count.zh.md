# Agent Note: 可配置的工作区会话数

Status: implemented

[English](2026-08-28-workspace-session-count.md) | 中文

## 问题

分组式工作区浏览器此前把每个折叠工作区固定在五行会话。同一个上限在大屏上浪费可用高度，对偏好密集侧栏的用户又藏掉太多上下文。

## 决策

工作区视图 store 在分组与排序偏好旁边持久化 `collapsedSessionCount`。取值是 5 到 20 的整数或 `auto`，默认仍为五。有两处入口写入它：既有的视图选项菜单——它本就控制工作区列表如何呈现——以及给习惯在设置里找偏好的用户准备的「通用」设置行。两者调用同一个 store action，因此都不会成为第二个真相源。

自适应会观测分组树的高度，并在扣除分组标题装饰后估算每组的行数预算。结果会夹紧到同样的 5–20 区间。显式展开的分组无论此偏好如何，都继续显示全部会话。

## 验证

运行 ui-workspace 的组件测试、它的 TypeScript 构建，以及仓库的 `pnpm build` 命令。

## 曾考虑的替代方案

**把该数量存为宿主设置** — 否决，因为它是查看状态，与它并列的分组、排序偏好同属一类。宿主设置会为一个本就该在笔记本与外接显示器之间取不同值的量，引入设置 schema 和跨客户端同步通路。

**只提供自适应** — 否决，因为观测得到的行数预算会随窗口缩放而变，想要一个可预期侧栏的用户无法把它固定住。显式整数保持为默认，`auto` 是可选项。

**只提供固定整数** — 否决，因为固定默认值恰恰就是被抱怨的那件事：在高分辨率屏幕上，任何单一数字不是浪费就是局促。让 `auto` 与整数并存，才覆盖得住「合适的数量就是恰好放得下」这种情况。

## 后果

该设置只是浏览器本地的查看状态，不新增宿主设置 schema，也不新增会话事件。持久化的 store key 递增，因此更早的存量状态不会缺少这个新的必需字段。单列表模式忽略这项偏好，因为它没有按工作区折叠的控件。
