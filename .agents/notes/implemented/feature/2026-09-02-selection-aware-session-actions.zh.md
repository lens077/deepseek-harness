# Agent Note: Selection-Aware Session Actions

Status: implemented

[English](2026-09-02-selection-aware-session-actions.md) | 中文

## Problem

会话多选最初没有操作层。加入归档、工作区成员关系变更和永久删除后，需要统一规定右键点击的操作对象、操作入口的位置、哪些变更必须原子提交，以及为什么会话的规范 `cwd` 不可变时不能提供表面上的任意“移动”。

## Decision

右键点击未选中的活动会话时，选择范围替换为该会话；右键点击已选中的会话时，保留完整选择范围。上下文菜单作用于最终选择范围。为了避免单行选择挤占列表并造成误触，增加间距的操作栏只在选中两个及以上会话时出现：若选择范围完全属于一个工作区，操作栏显示在该工作区标题下；未分组、搜索、单列表和跨归属选择的操作栏显示在侧边栏分区标题下。

归档在[注册表全局归档集合](2026-07-31-session-archive-global-set.zh.md)上增加一次批量变更。Host 在写入一次归档集合前验证全部所选 ID，因此任一未知会话都会使完整选择失败。已归档会话保留日志和工作区记账位置，并显示在独立的“已归档”视图中；该视图提供取消归档和永久删除。已归档行不参与活动列表选择。

“移出工作区”是一次持久成员关系变更。该操作保留日志和 `cwd`，仅删除所选记账位置，清理无效嵌套位置，并提升父会话被移除后仍然存在的子会话。仅当所选会话当前均未分组且具有同一个规范 `cwd` 时，才能加入另一个工作区。客户端会复用已登记该路径的工作区；若不存在，则先登记该目录，再附加所选会话。界面不提供跨目录任意移动。

永久删除使用单独确认、级联后代的[会话删除操作](2026-09-01-irreversible-session-deletion.zh.md)。发起请求前，会移除其祖先也在选择范围内的后代根，避免重复级联。多个独立根按顺序且互相独立地删除：某个根被拒绝不会取消排在其后的根，因为这些级联之间没有共享状态，中止只会让本可删除的会话被无关失败牵连。失败时其余根仍会提交，弹窗会报告首个失败原因，只把仍未删除的根保留在选中状态以便重试，并且不会声称已经回滚。

## Alternatives considered

**将任意所选会话移动到任意工作区**——拒绝，因为工作区附加会验证规范 `Session.cwd === Workspace.path`。改写 `cwd` 会改变会话执行身份，并使保留日志声称自己运行在实际未使用的目录中。

**用并行的单会话调用实现批量归档**——拒绝，因为一次传输失败可能只隐藏部分选择。Host 批量方法先完成验证，再发布一次持久归档集合变更。

**把“移出工作区”视为删除**——拒绝，因为工作区只拥有分组元数据，不拥有会话日志。移出可通过兼容路径重新附加来恢复，而且绝不修改持久化日志。

**让已归档行加入活动列表选择**——拒绝，因为已归档视图是归档操作的恢复入口。该视图保持单行操作和逆向操作优先，避免一次手势混合隐藏状态与活动成员状态。

## Verification

工作区测试固定批量归档原子验证、成员关系原子更新、嵌套子会话提升和删除清理。Host 传输测试固定 RPC schema 与处理器。Runtime 和 ui-workspace 测试固定单次调用的批量归档投影、感知选择范围的右键语义、操作栏位置、兼容工作区创建、归档恢复和删除根去重。

## Consequences

选择范围仍是[多选决策](../architecture/2026-08-31-workspace-session-multi-selection.zh.md)规定的浏览器本地查看状态；操作会读取它，但不会持久化它。归档和成员关系操作各自通过一次注册表变更提交，永久删除则保留每个会话谱系更强的崩溃恢复协议。为了保留规范路径和明确的恢复入口，界面刻意不提供任意工作区移动，也不在“已归档”视图中提供批量选择。
