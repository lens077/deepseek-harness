# Agent Note：提问面板提供加载全部历史

Status: implemented

[English](2026-09-18-question-panel-load-all-history.md) | 中文

## Problem

已加载的事件窗口只是会话的一个后缀。只要更早的分页尚未载入，提问面板就会如实说明——"只列出已加载的提问，更早的提问尚未载入"——而全会话搜索无需载入它们即可回答查询（[诚实的提问搜索](2026-09-14-honest-question-search.zh.md)）。面板没有提供的，恰是提示所说缺失的那种阅读方式：想在一个长会话里逐条步进全部提问、或通读整份转录的读者，只有转录里一次一页的"加载更早"按钮和上一个提问箭头，每按一次一页，没有办法一次要求全部。

早先的 `onLoadAll` 随那篇笔记一起被移除，因为它在撒谎——名字承诺整个会话，实际只拉一页——也因为对于"找到某个提问"，搜索已让它多余。但对于"阅读"，它从来不是多余的。产品负责人要求把这个按钮作为明确的全历史加载找回来。

## Decision

轨道在搜索入口正下方常驻一个**加载全部历史**入口，恰好在 `hasMore` 成立或一次全量加载进行中时出现；无论面板是否打开它都在，因为它的位置说明了它服务于哪个搜索。按一次即在 `ChatView` 里置起 `loadingAll` 请求；一个 effect 在每页落地且仍有更早内容时再次发起既有的带锚定 `loadOlder` 路径，会话没有更早事件时清除请求。之后列表与步进箭头覆盖全部提问，该入口随面板的提示一起离开轨道。

某一页结束后窗口头部 seq 没有移动时，循环停止。运行时在分页失败后仍保持 `hasMore` 为真，因此只看 `hasMore` 的循环会无休止地重试一个持续性故障；以进度为准，失败或空页即结束请求并恢复按钮，由读者有意识地重试。

每一页都经由 `loadOlderAnchored`，它在请求前记下读者停留的那一行，前插落地时不会移动正在阅读的内容。因此加载全部与手动逐页回翻是同一个操作，只是一次请求，并带有同样的滚动保证。

这与搜索是不同的操作，搜索笔记量化过的代价是真实的：整份转录最终常驻于浏览器。但那是读者按下按钮所要求的，而不是打开面板的副作用——面板打开时不加载任何内容，按钮的名字说明它做什么。

## Alternatives considered

**面板只保留搜索，依赖"加载更早"**——被产品负责人否决：数百回合的会话需要一个手势就能要求全部历史，而"更早的提问尚未载入"的提示应当紧挨着载入它们的途径。

**面板打开时自动翻页**，如被移除的 `onLoadAll` 那样——否决；这正是搜索笔记所移除的行为，它让打开面板改变同一个查询的答案。

**只以 `hasMore` 驱动循环**——否决；运行时在分页失败后仍保持 `hasMore` 为真，循环会无休止地发出请求。头部 seq 的进度才是区分"页已落地"与"页已失败"的可观察量。

**把 `loadAll` 加入会话服务和 slot 契约**——暂不采用；该请求只是对既有 slot 能力在视图层的重复调用，为一个调用方拓宽 `ChatViewSlotProps` 正是 `packages/AGENTS.md` 所指的"单一调用方的公共方法"气味。若第二个表面也需要全部历史，循环再移入服务。

## Consequences

- `QuestionNavigator` 接受 `loadingAll` 与 `onLoadAll`；两个导航器测试固定按钮的出现条件与忙碌状态，两个 `ChatView` 测试固定循环的完成以及在无进度页上的停止。
- `.questionLoadAll` 重新有了渲染者，样式与搜索入口和箭头并列；进行中状态把图标换成转圈并禁用该入口，而不是把它变暗。
- `.questionPanel` 从轨道顶端垂下、与搜索入口齐平，高度以该起点封顶在输入框之上；此前锚在轨道底部时，常见视口高度下的全会话列表会被推出视口顶部。窄布局保留底部锚定，因为其轨道就在输入框上方。
- 诚实搜索笔记中"按钮已移除"的后果由本笔记取代：搜索仍然从不加载会话，而加载是一次明确的请求。
