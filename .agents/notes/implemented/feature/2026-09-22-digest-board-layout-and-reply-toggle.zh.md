# Agent Note: 汇总看板布局与结果显示开关

Status: implemented

[English](2026-09-22-digest-board-layout-and-reply-toggle.md) | 中文

## 问题

汇总收件箱按状态自上而下堆叠分区，每张卡片都在固定高度的滚动正文里带着收尾回答。同时跑很多会话的用户看收件箱只为一个问题——哪些会话现在需要我决定，哪些刚刚完成——而堆叠排布要先滚过恰好很长的那个分区才能回答。会话在状态间流动时，也会把下面的每个分区一起推动。回答文本让每张卡片高到几个会话就填满面板。

## 决定

[浏览状态 store](../../../../packages/client/ui-digest/src/client/stores.ts) 新增两项持久化偏好：`layout`（`sections` 或 `columns`，默认 `sections`）与 `showReply`（默认 `true`）。持久化键改为 `dsh.digest.view.v3`：重水合会整体替换值，旧的 v2 文档会让这两个字段变成 `undefined`。

`columns` 就是看板：[`selectColumns`](../../../../packages/client/ui-digest/src/client/select.ts) 把 `selectInbox` 产出的分区重组为按需要决定先后排列的列——等你决定、已完成（未读与已读合并）、运行中、失败——每列按最近活动时间最新在前。[非空布局决策](2026-09-26-digest-workspace-layout-and-running-work.zh.md)取代空列占位，并负责有内容的列如何分配空间。它读的是分区而不是原始行，因此时间窗、工作区过滤、已处理可见性与置顶准入规则仍只在一处；置顶的行留在自己状态的列里，已处理的行按结果归入已完成或失败。键盘环跟随屏幕上的那种排布。看板仅限桌面端：手机本来就只列一列，所以 `mobileView` 忽略存储的布局，也不提供开关。

关闭 `showReply` 会从已结束的卡片上去掉收尾回答与截断提示，并把提问压缩为两行；运行详情保留显示；头部、改动文件与全部操作保留，因此分诊不变，只是密度变了。开关位于桌面工具栏，手机端在总览工具栏与小布局的 更多操作 菜单内。[包 README](../../../../packages/client/ui-digest/README.zh.md) 负责面向用户的行为说明。

## 备选方案

**用看板取代分区。** 一个状态占主导时以及在手机上分区更好读；用户要的是新增一种排布，两者都按浏览器持久化。

**给置顶行单独一列。** 看板的价值是每个状态有固定位置；置顶列会从某个状态手里拿走一个等宽槽位，还会把置顶行移出说明它需要什么的那一列。置顶标记与 `5` 键原地照常可用。

**逐卡片的回答展开。** 每卡一个展开器保留的正是开关想逃离的高默认值；回答在会话里只差一次点击，每张卡片的 打开会话 都能到达。

## 后果

两种布局的按键说明都位于滚动内容之外的紧凑页脚；有内容的看板列各自滚动。中栏窄于 920px 时看板退为两列，面板主体整体滚动。模型侧没有任何变化。

[选择规则测试](../../../../packages/client/ui-digest/tests/select.client.spec.ts)覆盖列的分组与顺序；[面板测试](../../../../packages/client/ui-digest/tests/panel.client.spec.tsx)覆盖布局开关、看板的键盘环与操作、两种排布下的结果开关以及手机端行为。
