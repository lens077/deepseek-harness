# Agent Note：汇总面板中的项目待办文档

Status: implemented

[English](2026-09-19-project-todo-documents.md) | 中文

## 问题

GUI 已有的两个待办界面都是会话级的：模型的 `todo_write` 列表在下一轮开始时清空，用户的收件箱待办各自指向一个会话。在每个项目目录里维护一份 `TODO.md` 的用户——这是规划超出任何一次对话的工作的常见做法——无法跨项目查看这些文件，看不出哪个项目还有未完成项，也没有从某一条目通向该项目会话的路径。「我的哪些项目还有活等着」只能靠逐个打开目录来回答。

## 决定

### Host 扫描用户的文件并整体提供

`@deepseek-ai/dsh-project-todos` 是 `projectTodos` Remote 背后的 Host 插件。它把每个配置的根目录、根目录的每个直接子目录，以及（启用时）每个已注册工作区目录视为项目，在其下匹配配置的相对项目 glob 规则，并逐行解析匹配到的文档：无序与有序列表项都是条目，`[x]` 方框标记已完成，缩进给出深度，最近的标题给出所属小节，围栏代码块被跳过。结果——带文档与条目的项目、计数、使用的设置以及无法读取内容的警告——是由 `get` 提供、`rescan` 刷新的一份快照，并在扫描结果与上一次不同时以 `project-todos/changed` 发布。`readDocument` 返回已列出文档的文本并拒绝任何其他路径，因此快照就是浏览器可通过本服务读取的全部文件集合。

文档始终是用户自己的：这里不会写入它们。监视是有界的而非递归的——根目录向下两层，已列出的项目向下一层，已列出的文档直接监视——所以一个含有许多项目的大根目录只花费几十个目录监视而不是一次爬取；出现在规则第一层以下的文档要到下一次显式重新扫描才会被发现。监视器在多次扫描间持续存在，只增删变化的路径，因为每次扫描后重建的监视器会漏掉在其启动期间落地的事件。

### 扫描设置就是设置节

`roots`、`files` 与 `includeWorkspaces` 既是插件的组合条目，也通过 `installSettingsSection` 成为用户在 GUI 中无需重启即可编辑的 `project-todos` 设置节；固定边界（`maxDepth`、`maxFileBytes`、`maxItemsPerFile`、`watchDebounceMs`）留在组合中。相对路径的根目录或逃出项目的规则在加载时和写入时都被拒绝，因此扫描永远不会在无法使用的设置节上运行。工作区注册表的写入（`workspace` 域上的 `domain/changed`）也会触发重新扫描，从侧边栏注册的工作区就是这样加入扫描的。

### 收件箱多一个标签，加一个设置页

汇总面板新增 **项目待办** 标签：每个项目一个分区，带来源与计数；每个文档一个区块，带条目；以及只读的操作——在该项目里开一个会话（必要时把目录注册为工作区，并在输入框预填一行点名该文档的提示）、内联显示文档文本、用 Host 自己的应用打开文件或目录，以及重新扫描。扫描结果在标签首次显示时读取，只用收件箱的用户永远不会触发。同一插件基于 `project-todos` 作用域注册 **项目待办** 设置页：带原生目录选择器的根目录列表、按行编辑的规则，以及工作区开关。两者都放在 ui-digest 里，因为面板本就汇聚跨工作区状态，而设置页就是该标签自己的配置。

## 考虑过的替代方案

**通过文件列表 RPC 在客户端扫描。** 否决：文件访问与信任栅栏归 Host 所有；浏览器通过 `host.listDirectory` 遍历目录会对每个目录发一次请求，且无法监视任何东西。

**让面板通过改写文档来勾选条目。** 暂时否决：改写用户也在手动编辑的 Markdown 文件有覆盖编辑器未保存状态的风险，而勾选复选框在编辑器里同样快。Remote 是只读的；该限制记录在 README 中。

**把扫描结果存入存储域。** 否决：文件才是权威，扫描重算成本低；存储副本会成为会过期的第二权威。

**递归监视每个项目。** 否决：monorepo 检出这类根目录会让数千个目录进入监视；有界方案覆盖常见布局（顶层 `TODO.md`、`docs/TODO.md`），显式重新扫描覆盖其余情况。

**为标签和设置页单独建一个客户端包。** 否决：标签位于汇总面板的标签条内，那不是一个 slot，而设置页就是该标签自己的配置；单独的包需要在 ui-digest 里为唯一的注册方新增一个 slot。

## 后果

每个含待办文档的项目目录都能在一处看到，带未完成计数，且离该目录中的会话只有一步之遥。对被监视路径的文件编辑会在防抖窗口内反映到扫描结果中。

读取上次扫描之外的文档从构造上就不可能。普通项目符号算作未完成条目，因此混写笔记与任务的文档会列出每一个项目符号，除非使用复选框。ui-digest 需要 `remote.projectTodos` 命名空间，因此 Web 组合必须挂载该 Host 插件。

## 验证

Host 测试套件钉住了解析器（复选框、普通项、有序项、嵌套、标题、CRLF、围栏、预算）、设置校验、候选收集（根目录、子目录、跳过的目录、工作区、非目录路径）、不可读根目录与文档的警告、超大文档、只在变化时发布的按需重新扫描、并发重新扫描的合并、编辑与新建顶层文档触发的监视器重新扫描、工作区域与设置驱动的重新扫描、仅限已列出文档的读取，以及销毁。客户端套件钉住了控制器的读取/推送/重新扫描/读文档/销毁路径、设置策略与设置页、项目标签的渲染、折叠、筛选、操作与失败提示，以及插件的命名空间绑定、打开项目、打开路径与设置页注册。组装后的 Web 应用在 3081 端口上以临时 `DSH_HOME` 做了演练：Remote 提供了 `settings.yaml` 中配置的扫描，标签列出了项目，从设置页添加的根目录进入了扫描与文档，对已列出文档的编辑经监视器刷新了快照。
