# Agent Note: 提问条展开全文

Status: implemented

[English](2026-09-17-question-bar-full-text-expand.md) | 中文

> 扩展 [提问级会话界面](2026-09-02-question-level-session-surfaces.zh.md) 中的粘性提问条与 [会话提问导航](../architecture/2026-08-28-question-navigation.zh.md) 中的偏好设置。两项决策均不改变；本记录说明展开按钮及其位置偏好。

## 问题

粘性提问条把当前提问压缩在一行内，其余部分以省略号截断。对一段结构化的长提问——比如列出编号步骤的那种——它完全不可读：唯一能看到全文的途径是原生 `title` 提示，它有延迟、无样式、不能滚动，指针一动就消失。跳回提问又会丢失读者在答案中的位置，而提问条存在的意义正是保住这个位置。

## 决策

提问条增加一个展开按钮，在胶囊下方以面板打开提问全文；按钮位于哪一侧是一项偏好设置。

### 面板挂在停靠层内部

`QuestionBar` 持有 `expanded` 状态，把面板渲染为自身绝对定位盒子的子元素，`top: calc(100% + 6px)`，宽度与胶囊一致。因此它继承提问条的居中，且不占用流内高度：停靠层仍是零高度，视图中测量 `scrollHeight` 的跟随、前插锚定与分页逻辑都不受影响。面板高度上限为 `min(50vh, 420px)`，内部滚动，极长的提问也不会盖住对话记录。文本以 `pre-wrap` 渲染，保留提问自身的换行结构。

面板是一种临时的阅读辅助，而不是一种模式。Escape 与在提问条外部按下指针都会关闭它；`ChatView` 以提问为 key 渲染提问条，读者转到另一提问的答案时展开状态随之卸载；跳到提问则整个提问条卸载。按钮带有 `aria-expanded` 与指向面板的 `aria-controls`，标签在展开与收起之间切换。

### 位置是提问导航偏好中的一个字段

`QuestionNavigationSettings` 新增 `expandButtonSide: 'left' | 'right'`，默认 `right`，与快捷键共用同一套 schema 校验。位于右侧时按钮是胶囊末端、结果与计时之后的元素，符合从左到右阅读中"更多"控件的惯常位置；位于左侧时它在编号之前，这是需求明确点名的位置。`QuestionShortcutRow` 以单选组在触发范围旁提供这两个选项，`reset` 恢复为 `right`。

`ChatView` 中的提问条与快捷键 effect 现在通过同一个已绑定的 hook 读取偏好：`ChatViewInjected` 声明 `hooks: { questionNavigation }`，取代原先读取快照的回调。因此设置变更会立即重绘提问条；此前的回调每次渲染读一次快照，在下一次状态变化之前会一直显示旧的位置。

## 曾考虑的替代方案

**把胶囊撑高为多行而非增加面板。** 否决：提问条是固定 30px 的胶囊，停靠层内其他所有测量都以此为前提，而多行胶囊恰好会盖住读者正在阅读的答案文本。

**用现有 `Modal` 原语打开全文。** 否决：模态框会夺取焦点并压暗对话记录；读者只想瞥一眼提问再继续阅读，而不是切换上下文。

**单独的 `questionBar` 设置分区。** 否决：位置只是又一项提问导航偏好，应与它一同发布的快捷键和触发范围放在一起；新的命名空间字段需要自己的策略类、host 键和重置路径，只为一个布尔量级的选择。

**保留 `questionNavigation()` 回调，只为位置再加一个 `hooks` 条目。** 否决：同一事实走两条通道；且该回调本身就是客户端规则所警告的陈旧读取路径。

## 验证

`chat-view.client.spec.tsx` 新增两个用例：展开显示完全一致的文本，`aria-expanded`/`aria-controls` 正确绑定，Escape 与外部按下指针会收起而内部按下不会；按钮默认是最后一个子元素，偏好 store 发布 `left` 后无需滚动或切换提问即变为第一个子元素。`question-shortcut-row.client.spec.tsx` 覆盖单选组：默认右侧，选择左侧写入整个偏好对象，重置回到右侧。`submission-policy.client.spec.ts` 的字面量携带新字段。ui-conversation 的 TypeScript 工程编译通过，聚焦测试套件全部通过。

## 后果

产品可见：提问条末端多了一个 chevron 按钮，点击出现面板，通用设置中多了一个单选组。没有会话事件、wire 操作或模型可见输入的变化；偏好保存在现有的 `ui-conversation` 设置命名空间中。
