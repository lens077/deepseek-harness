# Agent Note: 手机端四入口导航

Status: implemented

[English](2026-09-06-phone-four-entry-navigation.md) | 中文

## 问题

桌面侧栏与对话争用手机窄屏的空间。用户需要查看工作、处理请求、浏览 Workspace 和开始对话，而不必操作压缩后的桌面控制栏。为每种状态单独设置底部入口会使导航拥挤。

## 决策

宽度小于 768px 时，[布局](../../../../packages/client/ui-layout/README.zh.md)使用全宽内容与固定手机导航。四个入口依次为总览、待处理、工作区和新会话；设置保留在顶部栏。桌面端保留分栏布局。框架持有临时导航状态，通过既有侧栏和中央覆盖层 slot 传递；功能插件继续拥有各自的数据与操作。

[待处理](../../../../packages/client/ui-digest/README.zh.md)将等待交互、完成未读的会话与既有个人待办列表放在一起。手动加入待办仍是由[持久化收件箱](2026-09-17-durable-session-inbox.zh.md)存储的用户决定，不是独立的手机任务域。项目待办文档与这些个人任务保持区分。

[工作区浏览](../../../../packages/client/ui-workspace/README.zh.md)依次从 Workspace 列表进入一个 Workspace 的 Session 列表，再进入对话。手机端新会话明确创建未分组的临时 Session。桌面端新会话保留其 Workspace 选择规则。

[对话 shell](../../../../packages/client/ui-conversation/README.zh.md)使用手机全宽，并将文件栏放在初始关闭的展开控件之后。临时 Session 已解析的 cwd 满足 composer 的目录前置条件，无需加入 Workspace；其他输入阻塞条件继续生效。[设置对话框](../../../../packages/client/ui-settings-general/README.zh.md)将分区导航放在内容上方的横向行中。这两种布局避免辅助导航占用主要内容宽度。

总览使用手机本地的标签选择状态，初始为收件箱；运行中的工作排在最前，计数提供只看运行中筛选。Workspace 筛选横向滚动，而不占用多行。

总览与待处理初始显示紧凑的会话标题，每个面板最多展开一条详情。此方式保持列表浏览密度，不移除既有提问、回复、文件与操作内容。工作区管理通过具有无障碍名称的顶部图标进入，不占用单独的文字行。

[信息性欢迎声明](../../../../packages/client/ui-settings-models/README.zh.md)跳过手机端呈现，不记录确认也不写入设置。安全与权限确认保留各自的行为。

[手机外观](../../../../packages/client/ui-theme/README.zh.md)将布局密度、字号与桌面排版分开，因此更紧凑的布局不会丢弃读者选择的字号。小布局减少可见导航标签，保留无障碍名称，并将总览筛选归入原生选择控件与更多操作。[任务流程条](../../../../packages/client/ui-task-flow/README.zh.md)在手机端按需启用，独立的流程视图仍然可用。Host scope 在既有命名空间中持久化这些偏好；远程 memory scope 仅将手机偏好持久化到同源浏览器存储，并在加载时通过 schema 校验。

## 考虑过的替代方案

**手机端继续使用压缩后的桌面控制栏。** 否决，因为控制栏占用对话空间，并在窄屏上保留桌面导航密度。

**为运行中、提问、完成未读、个人待办与新会话分别设置底部入口。** 否决，因为底部导航会变得拥挤；总览与待处理可以归组相关工作，而不增加更多入口。

**把设置放在底部导航中。** 否决，改用顶部栏，使四个固定入口服务于主要工作任务。

## 影响

手机导航改变呈现方式，不改变 Host 存储、Session 日志或个人待办的含义。功能插件仍负责各自的操作，手机与桌面布局读取同一份数据。手机导航状态是临时状态，而非持久化偏好。

持久化收件箱记录继续保持活跃，因为它负责持久化与未读状态推导；本记录负责手机导航决策，不替代这些规则。
