# Agent Note: 汇总面板键盘分诊——方向键、Tab、可配置 Enter、数字键按钮

Status: implemented

[English](2026-09-23-digest-panel-keyboard-triage.md) | 中文

## 问题

收件箱面板原本有一个键盘环（`j`/`k` 与 `↑`/`↓` 沿环移动、`Enter` 打开、`e`/`t`/`p`/`s` 对应已处理、待办、置顶、延后、`Escape` 关闭），但几乎没人找得到：唯一的说明是最后一个分区下方的一行字，看板上没有，按钮上也不显示按键。环序也是唯一的几何：在换行的分区网格里 `↓` 会移到右边那张卡片，看板上 `←`/`→` 没有作用，无法整个分区或整列地跳，**继续** 没有按键，`Enter` 固定为打开会话。

## 决定

[面板](../../../../packages/client/ui-digest/src/client/DigestPanel.tsx) 保留 `j`/`k`（加上 `Home`/`End`）的环，并在其上叠加另外三个轴；[包 README](../../../../packages/client/ui-digest/README.zh.md) 拥有面向用户的按键表。

**方向键按屏幕位置移动。** [`neighborCard`](../../../../packages/client/ui-digest/src/client/card-keys.ts) 在与焦点卡片在垂直于方向的轴上有重叠、且中心位于方向键那一侧的卡片里，选沿着方向最近的一张。因此 `←`/`→` 不出本行（看板上到达下一列并排的那张卡片），`↑`/`↓` 不出本列，只有焦点卡片正下方有卡片时才进入下一个分区；行或列的边缘让按键停下，`↓` 不会斜着漂到另一列更近的卡片。盒子在按键时由 `getBoundingClientRect` 取得；没有布局的文档（jsdom）报告空盒子，此时由环序顶上。

**Tab 跳分组。** body 或面板根元素持有焦点时，`Tab`/`Shift+Tab` 移到下一个或上一个非空分区（或看板列）的第一张卡片。到达任一端时，按[非空布局决策](2026-09-26-digest-workspace-layout-and-running-work.zh.md)恢复原生焦点遍历，使控件可达。按钮和输入框保留原生焦点遍历。

**Enter 可配置。** `ui-digest` 设置节新增 `enterAction`，取六个卡片操作之一，默认 `open`，在 **汇总面板** 页用单选选定。卡片提供该操作时（运行中的会话不能继续、标记已处理或延后；等待用户的会话不能继续或延后；置顶跟随其总开关）面板对焦点卡片执行它，否则打开会话，因此 `Enter` 永远不会失效。`Shift+Enter` 始终打开。

**数字键按下按钮。** `1`–`6` 遵循卡片按钮顺序（打开、继续、已处理、待办、置顶、延后），卡片没有该按钮时拒绝。每张桌面卡片都在可用按钮文字旁用 `<kbd>` 画出对应数字（aria-hidden，按钮名称保持原样）。[布局与运行详情决策](2026-09-26-digest-workspace-layout-and-running-work.zh.md)要求提示常显；只有外框选中的卡片接收快捷键操作。说明行现在会写出 Enter 的操作，并在两种布局里都出现——看板下方和分区之下。单字母 `e`/`t`/`p`/`s` 去掉了：它们是中文界面上的英文助记，留下就是第二套没画出来的方案。

**面板打开时接过焦点。** 开关快捷键在用户正在打字的地方按下，通常是输入框，面板盖住它但它仍持有焦点；按键于是被当成打字，面板忽略它们。打开时面板根元素（`tabIndex={-1}`）接过焦点并记住之前的元素，关闭时若中途没有别的元素拿走焦点就还回去。`Tab` 守卫在 body 之外也放行面板根元素。

**捕获阶段的数字键。** 侧栏置顶区默认在同一个 document 上把裸 `1`–`0` 绑到它的位置，并且比面板先注册，因此在冒泡阶段它会打开置顶会话并关掉面板。面板于是在收件箱标签打开期间于捕获阶段接住数字键，其他按键都在冒泡阶段处理，这样离按键更近的菜单或对话框仍先看到 `Escape` 和 `Enter`。关闭面板后数字键归还置顶区。

## 考虑过的替代方案

**保留或扩展字母键**（`o` 打开、`c` 继续）。没有哪个助记能跨语言存活，而字母正是不可发现的那部分。

**把 `Tab` 绑到顶部页签或时间窗口。** 用户选择了分组跳转；`Tab` 作为空间移动与方向键放在一起是合适的，顶部页签仍可点击。

**用计算出的列数做环序方向键。** `auto-fill` 的 `grid-template-columns` 同样无法在没有布局时读取，看板的列高又不相等；测量盒子用一条规则覆盖两者。

**修改置顶区的默认快捷键**以腾出数字键。那会为一个只是有时打开的界面破坏所有用户已发布的默认值；在面板生命周期内占用这些键是更小的侵入，并在页面和 README 里写明。

## 后果

没有 `enterAction` 的已存文档按 `open` 读取。用过 `e`/`t`/`p`/`s` 的用户需要重新学数字键；焦点卡片会显示它们。面板在收件箱标签打开期间，置顶区的数字键快捷键不可用。`Tab` 在非空分组的两端进入原生控件，持有焦点的原生控件保留自己的激活键。
