# Agent Note: 在预留导航空间中提供浏览器本地休息小助手

Status: implemented

[English](2026-09-26-rest-companion.md) | 中文

## 问题

装饰角色可以在工作时提供陪伴，但任意悬浮位置可能遮挡输入区或对话。动画也可能造成干扰，尤其是在手机上。这种交互不具有任务或模型含义，不需要引入网络请求或持久化会话历史。

## 决策

[休息小助手](../../../../packages/client/ui-companion/README.zh.md)初始位于侧边栏预留的 `sidebar.footer.action` 空间。桌面导航提供展开区域；手机顶部栏和折叠导航栏提供静止、可点击的按钮。此默认位置位于输入区之外。[可拖动小助手决策](2026-09-26-draggable-rest-companion.zh.md)允许用户显式移动角色，部分替代了位置限制；仅在本地运行和内置图片的理由保持不变。

插件拥有的单一展示状态存储保存由点击驱动的 `idle → greeting → sleeping → idle` 循环、收起状态和手动动效偏好。响应式重新挂载保留这些状态，页面重新加载则重置状态。紧凑布局和隐藏页面会暂停动效，减少动态效果偏好会禁用动画。在展开的侧边栏收起小助手会留下恢复按钮；紧凑导航按钮保持状态循环，不打开覆盖层。

此包不调用模型、不写入会话事件，也不提供声音、计时器或通知。两张 WebP 图片由用户提供的蓝色 Q 版女仆鲸鱼参考图在本地处理而成，直接嵌入浏览器打包产物，而不是从外部图片服务获取。[web-app 配置项](../../../../packages/bundle/web-app/cordis.patch.yml)默认禁用，由部署方显式启用。[用量菜单增强](2026-09-26-companion-usage-menu.zh.md)为既有用量视图添加独立入口，不改变这些保证或角色交互。

## 考虑过的备选方案

**让角色初始悬浮在任意位置。** 预留默认位置可以避免遮挡对话内容和输入控件，无需用户先移动角色；显式移动由可拖动小助手决策说明。

**将打招呼和休息表示为会话事件或日志事件。** 这些事件会暗示装饰并不具备的任务或模型含义。纯客户端展示使会话历史和模型上下文都保持不变。

**通过外部图片服务获取或生成图片。** 内置本地图片避免让装饰控件依赖运行时凭据、外部图片请求和服务可用性。

## 影响

停靠且展开的小助手占用导航空间，其状态不跨页面重新加载保留，也不跨浏览器同步。停靠的紧凑展示舍弃动画和展开控件，以保持手机和折叠导航栏布局不受遮挡。

此包不发布运行时不变量：交互状态来自单一本地展示状态存储，不存在可能发生偏离的独立观测。图片来源说明不授予上游角色许可；再分发前需要单独核实相关权利。

## 验证

[交互测试](../../../../packages/client/ui-companion/tests/companion.client.spec.tsx)约束状态循环、收起与恢复时的焦点、紧凑交互和动效控件。[插件生命周期测试](../../../../packages/client/ui-companion/tests/browser-plugin.client.spec.ts)检查感知声明的注册，以及注册内容、语言字典和监听器的移除。[组合后的浏览器场景](../../../../apps/web/tests/companion.e2e.ts)验证键盘交互、可读状态快照、与输入区分离、减少动态效果、响应式状态保留、矮窗口控件，以及不变的手机四入口导航。
