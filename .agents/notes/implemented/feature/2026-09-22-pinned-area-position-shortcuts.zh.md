# Agent Note：置顶区位置快捷键

Status: implemented

[English](2026-09-22-pinned-area-position-shortcuts.md) | 中文

## 问题

[侧栏与汇总中的置顶会话](2026-09-11-pinned-sessions-in-sidebar-and-digest.zh.md)引入的侧栏 **置顶** 区列出了用户正在关注的 Session，但要到达其中一个仍需要鼠标：找到那一行，点击它。在多个活跃 Session 之间来回切换的用户希望按一个键打开第一个置顶行，按另一个键打开第二个，以此类推，就像浏览器用 ⌘1…⌘9 切换标签页。这些按键必须由用户自己选择——通过按下来录制，而不是作为文本输入——并且不能绑定到操作系统或浏览器层面，否则会在每个窗口触发。用户选定的组合如果浏览器或操作系统已经在响应（⌘T、Ctrl+1、⌘Q、Alt+F4），页面可能永远收不到，所以必须在绑定前告知用户。

## 决定

置顶区为每个列出的位置绑定一个按键组合，通过按键录制并附带冲突提示，只响应本标签页的 `keydown` 事件。

### 绑定位置，而不是 Session

工作区 viewing store 中的 `pinnedShortcuts` 是十个条目的列表，按行序对应置顶区的每个位置，每项是规范的 `[Ctrl+][Meta+][Alt+][Shift+]Key` 字符串或 `null`。默认是数字键行，`1` 到 `9` 再到 `0`。`pinnedShortcutsEnabled`（默认开）关闭整个列表而不丢失它。两者随其余 viewing 状态一起持久化（持久化键升到 `v12`），因此绑定是浏览器本地的：它们从不到达 Host，每个浏览器配置各保留一份。把组合绑定到某个位置会把它从任何其他位置释放，因此一个组合恰好打开一行。

位置是 `pinnedRows` 中的槽位，即该区绘制的同一份按最近时间排序的列表，因此每行佩戴的键帽就是监听器读取的事实。通过组合打开会运行与点击相同的 `openPinnedRow`：Session 被打开，置顶标记保留（用户放在那里就是为了回来），仅按状态列出的行则被移除直到其状态变化，因此置顶行是用户能学会的键盘，而状态行表现得像收件箱。

### 本标签页 document 上的一个监听器

在置顶启用、侧栏区被组合进来且快捷键开启期间，无论折叠与否，`WorkspaceBrowser` 都在 `document` 上挂一个 `keydown` 监听器。监听器跳过更靠近目标的组件已经 default-prevented 的事件（录制器、菜单），匹配事件拼出的组合所对应的第一个位置，让不带 Ctrl、Meta 或 Alt 的组合在 input、textarea、select 与 contenteditable 宿主（输入区）内保持静默，否则阻止默认行为并打开该位置的行。页面之外没有任何注册：关闭标签页即结束快捷键。

### 按键录制，冲突提示

置顶区的 ⋯ 菜单新增 **快捷键** 组：**启用快捷键**（保持菜单打开的勾选项）和 **编辑快捷键…**，后者会开启快捷键、展开置顶区，并在标题与行之间打开一个内联编辑器。编辑器显示十个键帽，每位一个，外加 **数字键 1–0** 与 **全部清除**。点击键帽开始在其上录制：下一次 keydown 由 `spellPinShortcut` 拼写（布局报告时取 `event.code` 中的物理字母或数字，修饰键按规范顺序），单独的修饰键、IME 组合或按键重复会被等待跳过，Tab、Enter、Esc、Space、Backspace、Delete 以及字母、数字、方向键、Home/End/PageUp/PageDown 与 F1–F12 之外的按键会被拒绝并显示状态行。Escape 取消，Backspace 或 Delete 清除该位置，失去焦点则取消。随后 `pinShortcutConflict` 按检测到的平台（`navigator.userAgentData.platform`，其次 `navigator.platform`，再次 user agent）分类该组合：浏览器自身的绑定（macOS 上 ⌘ 加字母、数字或方向键；Windows 与 Linux 上 Ctrl 加字母或数字、Ctrl+PageUp/PageDown、Alt+←/→/Home/D/E/F，以及裸 F1/F3/F5/F6/F7/F10/F11/F12）或操作系统的绑定（macOS 上 ⌘Q/H/M、⌘⇧3/4/5、⌃⌘ 组合、Ctrl+方向键与功能键；其他平台上 Win/Super 组合、Alt+F4、Ctrl+Alt+方向键，Linux 上另有 Ctrl+Alt+T/L 与 Alt+功能键）。未被占用的组合立即绑定；被占用的组合以警示色停留在键帽中，并由一条 `role="alert"` 说明另一方是谁，提供 **仍然绑定** 或 **重新录制**。键帽下方的提示指出不带修饰键的组合在输入框聚焦时保持静默，仅在绑定了这类组合时显示。

组合由 `formatPinShortcut` 以平台记法绘制：macOS 上 `⌃⌥⇧⌘` 字形连写，其他平台为 `Ctrl+Alt+Shift+Win`（或 `Super`）。每个置顶行的 `SessionNodeItem` 接收一个 `shortcut` 标签，在标题与时间之间画成 `<kbd>` 键帽，悬停时保留，这样伸手去按时仍能读到；快捷键关闭时键帽隐藏。

`pin-shortcuts.ts` 是 `ui-workspace` 拥有的纯模块；汇总的开关快捷键录制器在 `ui-digest` 中解决相邻的问题，而功能插件不得导入另一个插件的值，因此两者在出现共享拥有者之前保持独立。

## 考虑过的替代方案

**把组合绑定到 Session id。** 否决：用户要的是“第一个置顶 Session、第二个……”，按 Session 键控的映射会在其 Session 取消置顶时悄悄让绑定失效，而顶上来的那一行却没有绑定。位置还让十个键帽成为用户学一次就够的固定键盘。

**把绑定存进持久化的 `session-pins` 设置。** 否决：用户要求只在本标签页生效而不是全局绑定，而且组合的含义取决于用户面前的键盘和浏览器；浏览器本地的 viewing 偏好正是折叠与自动置顶移除已经使用的座位。

**用文本框输入组合。** 被需求否决：输入 `Ctrl+1` 会引入拼写错误和布局混淆，而按下组合录制的正是监听器将看到的东西，包括物理键。

**直接拒绝冲突的组合。** 否决：浏览器与系统的表因版本、扩展和窗口管理器而异，在浏览器里重绑了 ⌘1 的用户应当能在这里使用它。带明确 **仍然绑定** 的警告把决定留给用户，同时让风险可见。

**组合打开带标记的行时取消其置顶。** 使用后否决：会移除自身目标的组合把键盘变成了会弹出的栈，第二次按下到达的是与键帽承诺不同的 Session；标记属于用户，置顶区只能清除按状态的列出。

**让无修饰键的组合在侧栏之外全部静默。** 否决：快捷键的意义就是从用户所在的任何地方到达置顶行；只有可编辑字段——按键意味着打字——才需要静默。

**复用 `ui-digest` 的 `toggle-shortcut.ts`。** 被 client 导出纪律否决：功能插件不得在运行时导入另一个功能插件的值。把录制器提升为共享拥有者的工作延后到出现第三个消费者时。

## 结果

每个置顶行现在都带有键帽，只要焦点不在可编辑字段内，数字键就会打开置顶行；不喜欢这一点的用户可以清空列表或在 ⋯ 菜单里关闭该组。`dsh.workspace.view.v11` 的持久化 viewing 状态被 `v12` 键弃用；分组、排序、展开与折叠偏好会重置一次。用户在冲突警告之上绑定的组合仍可能被浏览器拿走（⌘W 在页面看到之前就关闭了标签页）；警告是唯一的防线。冲突表是精选而非穷尽的，与其测试一起放在 `pin-shortcuts.ts` 旁。

## 验证

`ui-workspace` 的 `pin-shortcuts.client.spec.ts` 固定平台检测、组合拼写（物理码、瞬态键、被拒绝的键）、精确匹配、命令修饰键规则、可编辑目标规则、各平台的冲突表、各平台的记法，以及“绑定即释放别处”的规则；浏览器 spec 固定行键帽、数字键按下打开带标记的行且保留标记并移除按状态列出的行、在搜索框内以及 default-prevented 或未匹配按键时的静默、菜单开关与设置关闭的情况、带命令修饰键的组合在输入框内触发、录制器的状态、拒绝、瞬态等待、绑定、释放、Escape、失焦、Backspace、预设、清除、关闭，以及带 **仍然绑定** 与 **重新录制** 的冲突流程。
