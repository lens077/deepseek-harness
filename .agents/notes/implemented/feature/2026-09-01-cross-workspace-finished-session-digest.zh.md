# Agent Note: 跨工作区已完成会话汇总

Status: implemented

[English](2026-09-01-cross-workspace-finished-session-digest.md) | 中文

## 问题

用户可以在多个工作区同时运行许多 agent 对话，但会话树只能回答这些对话在哪里、是否仍在活动。确认已完成的工作需要逐行打开，而瞬时的未查看完成标记会在导航或进程重启后消失。所需摘要已经存在于持久会话事件中：最新的直接人类提问、助手的结束回复与轮次结局。

## 决策

Web 应用提供一个覆盖整个中间栏的跨工作区汇总界面。位于「新会话」与工作区浏览区之间的 `sidebar.nav.entry` 行切换一个 `center.overlay` 条目，无需替换常驻的对话组件。面板在响应式网格中从左到右排列已结束的会话，支持按工作区或最近活动分组；进行中的工作不进入网格，只显示数量。

每张卡片代表一个用户可见的顶层会话。上半部分是最新一条 `source.kind` 为 `user` 的 `user/message`；注入上下文、压缩检查点与续跑消息均不算直接提问。下半部分是该提问之后最新的非空 `assistant/message`。`turn/end` 原因关闭卡片：`completed` 使用要求的绿色上边框，其他终止原因仍以失败边框显示。空白会话与 `origin: 'subagent'` 的行被排除，避免同一项委托任务在父会话旁再次计数。

`@deepseek-ai/dsh-session-digest` 在现有的[会话投影系统](../../proposed/architecture/2026-07-27-session-projection-and-command-log.zh.md)中注册 `sessionDigest` 单元。该单元折叠已提交的日志事件，在新的直接提问落地时重置回复与结局，并保存有界的提问与回答预览及其截断标记。标准会话列表投影块为已附着与冷会话携带该值；持久投影缓存无需加载或附着每份日志即可提供冷行。客户端不增加拦截 store、发送监听、轮询路径或模型调用。

`@deepseek-ai/dsh-client-ui-digest` 通过既有全局会话 hook 读取 `SessionSummary.projectionValues.sessionDigest`。侧边栏入口与面板共享一个声明式视图 store，只负责打开状态与分组方式。每张卡片完整显示有界预览，并提供独立的「打开会话」操作。该操作会关闭面板并打开对应会话，因此阅读内容不会意外跳转，所请求的结果会直接显示在中间栏。被截断的回复引导用户通过该路径查看完整内容，而不会为了读取完整历史而附着每个已列出的会话。

## 考虑过的替代方案

**在浏览器全局 store 中捕获提问与回复。** 否决，因为发送时观察会在宿主提交前发布状态，无法覆盖其他客户端与已有会话，并且刷新后失去权威性。会话事件已经提供已提交、可回放的消息。

**每轮结束后生成 LLM 摘要。** 否决，因为持久助手消息已经逐字可用。辅助请求会增加延迟、成本、失败模式与第二份结果解释，却不是该导航界面的必要条件。

**在每行会话列表投影值中携带完整回复。** 否决，因为每个列表行都会携带全部客户端可见投影键。有界预览让列表载荷与会话数保持成比例；完整历史保留在显式会话导航之后。

**复用瞬时 `completed` 列表位。** 否决，因为它表达的是「在未选中时完成且尚未打开」，而非持久任务完成。卡片从已记录的 `turn/end` 派生完成状态，因此查看卡片不会移除它。

**在侧边栏内渲染汇总内容。** 否决，因为侧边栏在 264–420 px 宽度内负责导航。侧边栏只提供入口；中间栏负责内容密度与从左到右的卡片布局。

## 后果

面板无需新增线路协议、模型请求或逐会话附着，即可重建跨工作区的已完成工作。刷新、其他浏览器客户端与冷态持久会话通过同一套投影和缓存机制收敛。

每张卡片描述一个会话中的最新一次直接提问，而非其中讨论过的每项任务。`completed` 分类的是轮次生命周期，并不证明现实工作一定成功。长回答只显示预览；在产品引入明确的时间或筛选策略前，全部已结束会话都会持续累积。在 `sessionDigest` 安装前写入的冷投影缓存没有该单元的行；对应会话会在一次冷投影读取后，或在打开并写入检查点后出现，而不会迫使零 I/O 列表路径扫描旧日志。

该功能新增两个可复用布局座位。`sidebar.nav.entry` 用于「新会话」下方的整页导航；`center.overlay` 用于必须保留侧边栏与详情栏所有权的中间栏界面。两者都保持为 slot 声明，布局包不导入具体功能。

## 验证

宿主测试固定直接用户消息过滤、多步轮次的最后回答选择、新提问重置、终止结局、有界预览、缺少单元时的行为与注册释放。客户端测试固定选择与分组、只计数运行中任务、卡片导航、截断提示、store 交互、语言字典一致性，以及两个 slot 注册的释放。完整客户端套件同时覆盖新的布局与侧边栏声明和样式表层级规则。
