# Agent Note：侧栏与汇总中的置顶会话

Status: implemented

[English](2026-09-11-pinned-sessions-in-sidebar-and-digest.md) | 中文

## 问题

同时跑着许多 Session 的用户没有办法表达"这几个优先"。[持久化会话收件箱](2026-09-17-durable-session-inbox.zh.md)已经按 Session 存了一个 `pinned` 标记，但设置和查看它的唯一入口是汇总面板里的卡片动作，而且置顶行排在收件箱分组的第四位。用户真正挑选 Session 的地方——会话浏览器——既没有置顶动作，也没有置顶列表，所以一个优先 Session 仍然要在它的 Workspace 里翻找。

## 决定

置顶成为会话浏览器的一等动作，只有一个持久化来源和一个设置页。

### 一个标记、一个提供方、一个消费座位

置顶标记仍然存放在 `@deepseek-ai/dsh-session-inbox` 里；每个 Session 不新增任何存储。已经拥有收件箱控制器的 `ui-digest` 提供 `ui-workspace` 在其契约里声明的可选 `sessionPins` 座位：一个携带 `{ enabled, sidebarArea, sidebarRows, pinnedSessionIds }` 的 `view` 可观察源，以及一个 `setPinned(sessionIds, pinned)` 写入器。`ui-workspace` 在 `ctx.inject(['sessionPins'], …)` 下把该视图镜像进浏览器的 `hooks` 区间，因此没有 `ui-digest` 的组合完全不渲染置顶入口，与 `sessionTodos` 座位隐藏"加入待办"的方式一致。只有 id 列表或策略真正变化时视图才发布新快照，所以无关的收件箱推送不会让行重新渲染。

### 会话浏览器负责置顶与列出

会话行的 ⋯ 菜单在 **重命名** 上方提供 **置顶** / **取消置顶**，多选右键菜单对所有选中行提供同一动作。浏览器在 **工作区** 标题上方渲染一个 **置顶** 区，高度固定为若干会话行（默认五行），置顶更多时在区内滚动；区内的行就是普通的 `SessionNodeItem`，因此状态点、悬浮卡、行菜单和感知选择的右键菜单与树中表现完全一致。置顶行按 Session 最近更新排序；已归档、空白、未知和子代理来源的 id 由 `deriveFlat` 旁边的纯函数 `derivePinned` 丢弃。空的置顶区显示一行提示而不是塌缩，这样用户要求的这块区域保持在原位。

### 汇总把置顶行排在最前

在收件箱中，**置顶** 分组移到最前：置顶的 Session 是用户明示的优先级，高于最新的未读回复。置顶行仍然不受时间窗口限制而被纳入。

### 一个设置页、三个开关和一个尺寸

一个 **置顶** 设置页（`settings.section` id `session-pins`，紧跟在 **项目待办** 之后）拥有持久化的 `session-pins` 命名空间：`enabled`（默认开）、`sidebarArea`（默认开）、`sidebarRows`（默认 5，范围 1–20）和 `digestSection`（默认开）。总开关隐藏所有置顶入口——菜单项、侧栏置顶区、卡片动作及其 `p` 键、汇总分组；两个细粒度开关各自移除一个界面，而标记本身保持持久化，因此重新启用后恢复同一置顶集合。

## 备选方案

**由 `ui-digest` 向一个新的侧栏槽位渲染置顶区。** 否决：这些行会成为第二种更弱的会话行（没有状态边框、没有行菜单、没有选择），并且 `ui-sidebar` 会为只有一个插件填充的槽位增加一个洞。浏览器已经拥有所有行的呈现；座位只需要携带 id 和策略。

**把置顶标记投影进会话列表（`projectionValues`）。** 否决：该标记是存放在收件箱旁车里的用户决定，不是 Session 日志的折叠结果；投影它会制造第二个权威来源，并为一个浏览器侧需求改动 Host。

**通过 `provideRoot` 提供全局 `usePinnedSessions` 标准钩子。** 否决：标准钩子在每个组件的 props 上都是必需的，没有 `ui-digest` 的组合会类型失败或需要桩；可选座位靠缺席自然降级。

**把设置存进现有的 `ui-digest` 命名空间。** 否决：该页是一个拥有自己默认值的独立设置入口，侧栏开关和行数关心的是会话浏览器而非汇总徽标；专用命名空间保持一页对应一个命名空间。

**保持汇总分组在第四位。** 否决：需求是优先处理；被运行中工作压住的置顶行违背了这一点。

## 后果

置顶从用户正在看的那一行即可触达，侧栏置顶区、汇总分组以及连接到同一 Host 的每个浏览器看到同一置顶集合。没有 `ui-digest` 的组合不受影响。侧栏置顶区只要启用就占据固定高度（行数 × 行高），包括为空时；想要拿回空间的用户可以在设置页关闭该区或整个功能。汇总的分组顺序对所有人改变，已存储的 `ui-digest` 设置不受影响。升级后尚未重启的 Host 没有 `session-pins` 命名空间，因此该页报告设置不可用，并在重启前沿用默认值（全部开启、五行）。

## 验证

`ui-workspace` 测试固定菜单项的位置与文案、置顶区的排序、尺寸、空态与门控、右键菜单动作，以及座位镜像的跟随与重置生命周期。`ui-digest` 测试固定 node 半边的 `session-pins` schema 与默认值、设置页的写入与禁用状态、`sessionPins` 提供方的稳定快照与失败上报，以及带 `pinnedSection` 门控的收件箱置顶优先分组。
