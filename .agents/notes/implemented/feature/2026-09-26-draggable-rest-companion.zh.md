# Agent Note: 由用户控制休息小助手的位置

Status: implemented

[English](2026-09-26-draggable-rest-companion.md) | 中文

## 问题

预留导航空间可以避免自动遮挡，但固定位置的小助手不允许用户选择摆放位置。移动角色必须与打招呼区分开来，角色也需要一个随时可用的方式返回导航。

## 决策

[小助手](../../../../packages/client/ui-companion/README.zh.md)初始停靠在导航中，并允许用户通过鼠标、笔或触摸显式拖动。主指针移动至少 6 个 CSS 像素后，角色脱离停靠区域，采用相对于视口的固定位置，并抑制随后产生的点击。普通点击仍执行状态循环或恢复展开。角色获得焦点时，方向键每次移动 16 个 CSS 像素；**Home** 键和悬浮时的**归位**控件将角色放回导航。紧凑布局也保留归位控件。

[拖动处理器](../../../../packages/client/ui-companion/src/client/useCompanionDrag.ts)在移动后，以及视口或小助手尺寸变化后限制位置。可视视口的尺寸与滚动观测也会在软键盘或缩放改变可见区域时限制位置。位置保存在现有的本地展示状态存储中：响应式重新挂载会保留位置，页面重新加载则恢复为停靠状态。拖动期间暂停动画，不改变角色状态或手动动效偏好。

此决策部分替代[预留位置决策](2026-09-26-rest-companion.zh.md)，但不改变默认位置或仅在本地运行的理由。用户选择的悬浮位置可能遮挡对话内容或输入区。此包仍然不调用模型、不写入会话事件、不向外部请求图片，也不提供声音、计时器或通知。

## 考虑过的备选方案

**让角色始终停靠在导航中。** 这可以避免遮挡，但不满足用户控制位置的需求。初始停靠与显式归位控件既保留了不遮挡内容的默认位置，又不禁止移动。

## 影响

用户控制位置意味着不再保证任何位置都没有遮挡。视口范围限制让角色保持可操作，但不会避开对话或输入区内容；移动或归位可以移开遮挡。位置是临时状态，不跨浏览器同步，也不增加需要运行时不变量的独立观测。

## 验证

[组合后的浏览器场景](../../../../apps/web/tests/companion.e2e.ts)验证鼠标和触摸拖动不触发状态切换、随后普通点击仍生效、缩小到手机尺寸后的范围限制、紧凑控件布局，以及归位到手机顶部栏。[手势测试](../../../../packages/client/ui-companion/tests/drag.client.spec.tsx)覆盖取消、指针捕获清理、键盘移动和可视视口变化。实体触控笔硬件尚未验证。
