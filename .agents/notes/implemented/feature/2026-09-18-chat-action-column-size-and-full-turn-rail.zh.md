# Agent Note: 可调节的 Chat 操作按钮列与整列高度的轮次刻度轨道

Status: implemented

[English](2026-09-18-chat-action-column-size-and-full-turn-rail.md) | 中文

## Problem

转录右缘有两个浮动表面：提问导航的操作按钮列（搜索、加载全部、上一条、下一条、回到底部）与其旁边的轮次刻度轨道。把这些按钮从 34px 放大到 42px 后暴露出三个缺陷。

转录内容跑到了按钮下方。滚动容器两侧留白固定为 `输入区留白 + 16px`，于是右对齐的数字、宽表格或任何满宽行都会顶到视口边缘，按钮直接盖在上面。

轨道无法显示一个会话的全部轮次。它的高度被限制为 `min(自然高度, band - 64px, 420px)` 并在整个 band 内居中，因此长会话大约只显示四个刻度，其余滚出视野，也没有任何提示说明刻度还在延伸。22px 的刻度命中区域还超出了 6px 的阶梯内边距，导致静止的轨道报告出 5px 无用滚动。

按钮尺寸是硬编码常量：需要更大点击目标的用户无法要求，想要拿回阅读宽度的用户也无法撤销。

## Decision

**一个尺寸偏好驱动整列。** `ChatSettings` 新增 `actionControlSize`（整数 CSS 像素，26–58，默认 34——即该列可调之前的尺寸），由 Host schema 校验。`ActionControlSizePolicy` 与 `TranscriptViewPolicy` 并列，把它镜像到浏览器 store，设置 → 通用的一行以 4px 步长缩放。缩放网格锚定在默认值而非零上，因此 34 与引发本次改动的 42 都可达，两端也落在网格上。`clampActionControlSize` 让两端的缩放运算停在一个被接受的答案上。

`ChatView` 把该值以 `--dsh-chat-action-size` 重新发布到其根元素。操作按钮列、轨道宽度、刻度几何（`--turn-tick`，按尺寸的 0.48/0.7/1.4/1.6 缩放）、搜索面板偏移与转录留白都读取它，因此整列作为一个整体移动。

**留白对称且被预留。** `.scroll` 两侧留白变为 `max(输入区留白 + 16px, 尺寸 + 32px)`。两侧同时加宽，因为单侧预留会把居中的消息列推离输入框的轴线；手机断点恢复原留白，那里按钮列停在输入区上方而非转录旁边。实测：34px 与 50px 下，转录内容盒与按钮之间都保持 28px 恒定间距。

**轨道占满按钮列上方的区域。** `QuestionNavigator` 观察自身渲染高度并上报；`ChatView` 直接把它写到根元素的 `--dsh-chat-action-column`，而不是放进 React state——该值只有 CSS 读取，而每次 resize 触发一次渲染会搭上每一次流式提交。轨道由 band 减去该列及其偏移得到 `--turn-rail-free`，去掉 420px 上限，并在该空闲区间内居中——变高的轨道不再可能触到按钮。`RAIL_INSET_PX` 从 6 改为 12，即刻度命中高度的一半，于是静止的轨道不再报告幻影滚动。

**位置由读者决定，且默认贴靠按钮。** 多数会话轮次不多，因此轨道默认不再占用一列转录宽度：`turnRailPlacement`（`stacked` | `column`，默认 `stacked`）与 `turnRailAlignment`（`top` | `center` | `bottom`，默认 `top`）加入同一持久化 section，一行设置以列表给出四个去处——因为贴靠位没有自己的对齐方式。贴靠时轨道与按钮同列，底端停在按钮上方一个间距处，因此最新 Turn 的刻度正对搜索按钮，阶梯也停在最新一端而非最旧一端。独立一列时保持原有行为，可占用整个可视高度，并从其对齐方式所指的一端开始。转录的预留随之变化：贴靠预留一个按钮宽度，独立一列预留两个。

**提问面板改为向上展开。** 它原先锚定在按钮列顶部，而那时按钮列就在屏幕上方。按钮列移到输入区地板后，面板从视口底部附近开始、溢出到屏幕之外，其列表也失去受限高度，于是在上面滚动滚轮毫无反应。现在面板锚定在按钮列的底部，高度上限取该地板到转录可视区顶部之间的空间，列表自行吸收滚动溢出，滚到尽头也不会带动后面的转录。

**两列以同一方式定位。** 轨道改为 `position: fixed`，与按钮一样从输入区地板起算偏移。以滚动容器定位时它会偏离按钮列一个滚动条槽的宽度——本机为 8px——而这恰恰是贴靠位要解决的对齐问题。

**翻页入口标示溢出。** 滚轮本就能滚动阶梯；现在仍可滚动的一端会出现 `.edge` 按钮，每次翻过框高的 80%。它们是扁平的，与下方圆形浮起按钮不同，因为它们只移动阶梯，而后者执行转录命令。

**浏览器校验收到的尺寸。** `adopt()` 校验 `actionControlSize` 而不是信任 section 类型：早于该字段的 Host 会发布不含它的 section，由此得到的 `NaN` 会把整列宽度塌缩为零。`actionSizeStyle` 应用同样的防护，因为自定义属性声明的兜底值无法挽救一个无效值。

## Alternatives considered

**只在右侧预留留白。** 占用空间更小，但消息列在留白盒内居中，单侧预留会明显把转录推离输入框的轴线。

**用 CSS 按条目数推算按钮列高度。** 该列的条目会变化（加载全部会出现和消失），而轨道是它的兄弟节点而非后代；测量渲染后的列，是唯一无需在两处重复条目规则又能保持正确的答案。

**把轨道贴底并初始滚动到最新轮次。** 曾经实现过，被用户判定为迷失方向而否决。轨道保留其居中静止位置与既有的活动刻度跟随，只有上限发生变化。

**用具名尺寸菜单替代 px 步进器。** 需求是按 px 放大和缩小；步进器直接读出当前像素尺寸，九个档位也不需要一套命名方案。

## Consequences

- Host 半边注册 schema，因此运行中的 `dsh web` 必须重启后新字段才会持久化；在此之前浏览器回落到 34px，Host 会拒绝该写入。
- 之后任何进入该留白区的表面都应读取 `--dsh-chat-action-size` 而不是另写像素值，并从输入区地板而非滚动盒起算偏移。
- 轨道阶梯的静止位置现在取决于位置：贴靠时停在最新 Turn，独立一列时停在其对齐方式所指的一端。该位置每种位置只应用一次，因此读者滚动轨道后仍保留自己的位置。
- `packages/client/ui-chat/tests/action-control-size.client.spec.ts` 固定了吸附网格、两端范围、Host 版本错配的回落与采纳；`action-control-size-row.client.spec.tsx` 固定了步进器及其禁用端；`chat-apply.client.spec.tsx` 固定了两项注册与其注入面；`turn-rail-layout.client.spec.ts` 固定了按字段持久化、快照标识与旧版 Host 值的回落，`turn-rail-layout-row.client.spec.tsx` 固定了四个去处。`chat-view.client.spec.tsx` 中的轨道几何预期随新内边距一并更新。
