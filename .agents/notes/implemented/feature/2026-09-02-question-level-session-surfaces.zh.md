# Agent Note：以提问为单位的会话表面

Status: implemented

[English](2026-09-02-question-level-session-surfaces.md) | 中文

> 部分被取代：紧凑模式已由 [提问导轨收缩为只做步进](2026-09-02-question-rail-reduced-to-stepping.zh.md) 移除，该记录删除了所有重复绘制提问索引的界面。归属规则、提问栏、回合回顾、标签页标记以及两处接缝依然有效。

## 问题

在一个会话里连续跑多个长任务的读者，无法判断某段回答在回答什么。回合结束时读者停在转录区底部，而开启这个回合的消息在几千像素之上；文件侧栏只列出**整个会话**改过的文件，没有办法看到**这次提问**改了什么；浏览器标签页也不会告诉他仍在运行的工作何时结束。

[提问导航](../architecture/2026-08-28-question-navigation.zh.md)解决的是相邻问题——抵达另一个提问——而它的代价也一样：跳到提问处就丢掉了答案，读者要再跳一次才能回来。导航移动的是读者，没有任何东西把提问留在原地。

## 决定

一份推导，四个表面。`chat/turn-summary.ts` 把已加载的提问与回答它们的回合关联起来，之后每个需要指名提问的表面都读这一份索引。

### 关联规则

一个提问属于**在它之前（含同位）最后开启的那个回合**。日志就是这个顺序：`turn/start` 先开启回合，循环**之后**才写入进入其首个 step 的 `user/message` 事件。因此一批排队消息共享同一个回合，其中第一条是该回合展示的开场提问。

这与 [ui-session-files](../../../../packages/client/ui-session-files) 归属文件改动所用的 seq-到-turn 规则完全相同，因此一个提问与其回合改过的文件不会在归属上产生分歧。早先的草稿把每个提问关联到它**之后**第一个开启的回合——直觉上的顺序，而且是反的；一份快照日志给出了定论。

`buildTurnGroups` 用同一套边界按 anchor seq 归属 Node，并且**按回合**而非按连续段产出分组：回合是读者折叠的单位，无论其 Node 如何排列都必须保持为一行。

### 四个表面

**顶部粘性提问条**位于转录区滚动容器顶部，指名读者当前所处答案对应的提问，并带上该回合的结果、实时计时与改动文件数。只有当该提问所在行完全越过滚动容器上边缘后它才出现，并且渲染在一个**零高度的 sticky 停靠层**里：聊天视图的跟随、前插锚定与分页逻辑都要测量 `scrollHeight`，若这条在流内进出，每次变化都会移动读者的位置。

**回合回执行**出现在跨度不少于 `RECAP_MIN_ROWS` 行的已完成回合末尾。在不测量布局的前提下，行数是滚动距离唯一可用的代理量。短回合不会出现：它的提问仍在屏幕上，重述一遍只会让线性阅读的每个回合都多一行噪音。

**紧凑模式**把每个已结束回合折叠为一行——提问、结果、计时、文件数——而最新回合、任何仍在运行的回合以及读者手动展开的回合保持完整。折叠刚刚抵达的内容，等于藏起读者正在等的那个答案。该界面已不再发布：[提问导轨收缩为只做步进](2026-09-02-question-rail-reduced-to-stepping.zh.md) 将其作为绘制同一份索引的三个界面之一移除，此后正文不再存在「回合变成行」的模式。

**标签页标题标记**：任一会话运行中显示 `●`；最后一个运行在标签页处于隐藏状态时结束，则锁存 `✓`，并由送达该标记的那次访问清除。之所以锁存而非瞬时，是因为这次完成正是切走标签页的读者错过的事件。

### 两条接缝

这些表面横跨两个插件，因此每个方向都是通过 `ctx.get` 取用的可选服务，与既有的 `chatFileDiffs` 安排一致。

`ChatFileDiffs.forTurn` 按归属回合切分已记录的改动，ui-conversation 向它索取某回合的文件。它只覆盖本会话：后代会话的回合编号是它自己的，合并进来会把子智能体的第 3 轮算到父会话头上。

`chatQuestionIndex` 发布提问索引，ui-session-files 向它询问哪个回合属于哪个提问，并把文件侧栏按导致这些改动的提问分组，最新的在前，所有无法归属的收进唯一一个末尾分组。没有这个服务时侧栏保持扁平列表，而 `按提问`/`全部` 开关让那份列表始终只有一次点击之遥。

两者都按调用即时解析，因此任一 provider 的组入或组出都即时生效；两者也都以快照为键做记忆化——快照不可变且随变更整体替换。

## 验证

运行 ui-conversation、ui-session-files 与 ui-renderer 套件，通过 `tsc -b tsconfig.client.json` 做客户端类型检查，并运行 `pnpm run test:gui`。

## 备选方案

**把开场提问作为 turn 作用域 Location 数据发布，由 `conversation.chat.turnTail` 条目绘制回执行**——否决，因为回合的开场提问无法从它自己的 Context 抵达：`turn/start` 在 `user/message` 存在之前就创建了 Context，而 `reader.previous('input-message')` 返回的是最近的任意一条消息，注入的上下文消息会抢先命中。在聊天视图既有的 memo 里推导回执行既保持了单一索引，也不需要逐 Node 扫描——那本来就是 [Conversation Node 规则](../../../../packages/client/AGENTS.md)所禁止的。

**把当前提问放进会话头部**——否决，因为头部是跨视图标签共享的会话 chrome，而当前提问是一个滚动位置事实。头部一旦指名它，读者滚动的瞬间它就错了，对每个非转录视图也一直是错的。

**把文件侧栏做成常驻的提问大纲**——作为首选方案否决。导航器的展开面板已经是一份可搜索的提问列表；常驻副本花掉 240px 只省下一次点击，而且回答的仍是"带我去某处"，不是"我在读什么"。

**在 ui-session-files 内复制一份提问推导**——否决，因为侧栏本就在读会话快照，完全可以再走一遍。两份"什么算提问"的推导必然漂移，所以让索引以服务的形式跨越边界。

**从会话插件里再写一次 `document.title`**——否决，因为该事实归 ui-renderer 的 `DocumentTitle` 所有；运行标记是这个既有属主上的一个 prop。

## 后果

不新增 session 事件，也不改变模型可见内容：每个事实都从 Chat 投影与既有 timeline 推导而来，因此重放与分页仍只有一个权威。

聊天视图每次滚动的提问扫描改为对已渲染锚点的单趟遍历；原先的逐提问形式在长会话中是二次复杂度，现在同时还报告当前提问是否已离开视口。

两个测试 fixture 被修正而非绕开。`chat-snapshot-fixture` 用扁平的 `reason: 'completed'` 而非信封的 `data.reason.kind` 合成 `turn/end`，并把 `turn/start` 放在了该回合自身节点**之后**。两者都偏离日志，任何读取这两个事实的代码都会继承这份偏离。

紧凑模式与侧栏分组曾是逐次挂载的读者状态，刻意不做持久化：它们是此刻阅读某个会话的方式，而不是关于所有会话的偏好。该规则对侧栏分组依然适用；紧凑模式本身此后已被移除。
