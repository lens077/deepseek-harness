# Agent Note：被移除的唤醒消息在运行时上下文旁边不再消耗模型调用

状态：已实现

[English](2026-09-18-removed-wake-beside-runtime-context.md) | 中文

## 问题

回合的空步骤守卫通过查看步骤的消息列表来决定是否消耗一次模型调用。这个列表是已认领的收件箱消息，加上——只要注册了任何上下文段——系统提示词贡献的运行时上下文快照。一旦注册了上下文段（凡是挂载了沙箱策略的部署都会注册一个），在认领前被移除的唤醒消息会留下一个空认领但一条消息的步骤，回合便只带着快照去调用模型。ACP 测试夹具在为附加目录能力组合进沙箱策略的那一刻暴露了它：对已移除消息的 `prompt` 以 mock 脚本耗尽失败，而不是以取消收场。

## 决策

快照随已认领的消息一起走，绝不代替它：`preStep` 只在认领至少产生一条消息时才追加运行时上下文，因此守卫读到的就是步骤本身是否为空，而既有规则——"被移除的唤醒消息拥有回合边界，但不消耗模型调用"——无论是否存在上下文段都成立。非空认领的行为不变；快照仍在同一步骤中跟在已认领消息之后。

## 考虑过的替代方案

**让守卫检查认领而不是步骤消息。** 否决：守卫同时服务于把已进入步骤改写为空的 `agent/pre-step` 监听器，它必须继续读取交给它的决定。把快照挡在空步骤之外，同时修好了守卫的输入和模型本会看到的请求。

**让 ACP 夹具不挂沙箱策略。** 否决：桥接为 `session/new` 的目录校验注入 `sandboxPolicy`，夹具必须组合它；这个测试报告的是真实的循环缺陷，不是夹具缺口。

## 后果

唯一候选内容是运行时上下文快照的回合以 `completed` 关闭，没有步骤、没有 `user/message`、没有请求，与没有上下文段时的被移除唤醒情形一致。循环单元测试在注册了上下文段的情况下固定了这一点；ACP 的认领前取消测试在组合了策略的情况下通过。
