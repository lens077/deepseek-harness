# @deepseek-ai/dsh-session-digest

[English](README.md) | 中文

注册 `sessionDigest` 投影单元的函数插件：最新的人类提问、回答该提问的最后一条助手消息、该轮次的终止原因、该轮次改动的文件，以及之前提问的有界历史。它们从持久会话事件折叠而来，经由 session-projection 能力缝合层对外提供（注册表快照、变更流，以及全部投影载体：历史尾页、`session/projection` 推送帧、会话列表行）。它的存在意义是让客户端无需逐个打开会话、也无需任何模型调用，即可汇总跨工作区的已完成工作——参考消费者是 Web 汇总面板。

## 折叠语义

- `question` 保留 `source.kind` 为 `user` 的最新一条 `user/message`。其余所有 `user/message`——注入的工作区说明、时间上下文、压缩检查点、目标续跑轮次——属于模型可见表面而非人类提出的问题，一律忽略。
- 新提问会把上一条提问移入 `history`（其 seq、事件时间、文本、结果、回复时间和改动文件数，按最早在前排列，并按 `historyQuestions` 预算裁剪），并清空 `reply`、`outcome`、`replySeq`、`repliedAt` 与改动文件记录。因此最新提问仍在处理中的会话报告 `outcome: null`，而不会继承上一条提问的完成状态；消费者据此区分进行中与已完成的工作。`questionSeq` 与 `questionAt` 携带最新提问的日志 seq 和事件时间，是待办或对话跳转使用的地址。
- `changedFiles` 与 `changedFileCount` 来自修改类工具自己在 `tool/result` 里的记录——`dsh-tool-fs` 附加的 `diffs[].path` 列表——因此工具通过声明自己改了什么来参与，折叠从不根据工具名或文字猜测。计数覆盖当前提问轮次的每个不同路径；列表按 `changedFilePaths` 预算保留最先出现的路径。
- `reply` 保留提问之后最新的非空 `assistant/message`，因此多步轮次保留模型最后写下的总结，而非中间的工具调用步骤；`repliedAt` 是它的事件时间。没有前置提问的助手消息被忽略。
- `outcome` 镜像 `turn/end` 的原因判别式（`completed`、`error`、`aborted`、`blocked`、`max-tokens`、`interrupted`），在该轮次结束前保持 `null`。消费者据此区分真正成功与仅仅停止的轮次。
- 两段文本仅拼接 `text` 内容块——工具调用、图片与推理内容永不进入该值——并按配置预算截断，`questionTruncated` / `replyTruncated` 报告是否发生截断。`replySeq` 携带所保留消息的日志 seq，供通过 `session.history` 精确按需读取完整内容。
- 已组合的注册表始终提供该键，因此客户端读取值本身，而非键是否存在。

## 配置

| 键 | 默认值 | 含义 |
| --- | --- | --- |
| `questionChars` | `400` | 保留的提问字符数上限。 |
| `replyChars` | `1200` | 保留的回答字符数上限。 |
| `changedFilePaths` | `8` | 当前提问保留的改动文件路径数上限。 |
| `historyQuestions` | `30` | 保留的更早提问数上限。 |

该值随每一行 `session.list` 一同传输，因此这些预算限制的是列表载荷而非持久日志。调高会使每次列表响应变大；需要完整消息的消费者应改为通过 `session.history` 读取。非整数或非正值会导致插件加载失败。

## 组合

```yaml
- id: session-digest
  name: '@deepseek-ai/dsh-session-digest'
```

注入 `sessionProjections`——这是插件的全部目的；在没有该注册表的装配中纤程保持挂起，不注册任何内容。折叠完全在本地进行，不需要采集器、网络端点、账号或云凭据。

冷会话列表行由持久化投影缓存提供，因此希望为本进程从未附着过的会话生成汇总的部署，还需挂载 `@deepseek-ai/dsh-session-projection-cache`。

## 模型体验

无。插件只计算已记录会话事件的面向客户端读模型，不触及任何提示词、消息、模式、流或工具结果。

#### KV 缓存影响

无；插件从不组装或发送提供方请求。

## 已知限制与遗留工作

- **只有最新提问保留回答** —— 更早的提问以其结果和文件数留在 `history` 中，但没有回复文本；更早的回答只能通过会话本身查看。
- **被有界列表丢弃的路径可能被重复计数** —— 列表满了以后，后续结果里出现的、列表从未保留过的路径会被当作新路径计数；因此对于触及的不同文件数超过预算的轮次，计数是一个上界。
- **在该单元安装前写入的缓存没有汇总行** —— 已有冷会话会在一次冷投影读取后，或在被打开并写入检查点后出现；零 I/O 的会话列表不会仅因为安装了该单元就扫描每份旧日志。
- **修改预算不会重写已缓存的值** —— `stateVersion` 覆盖状态字段与折叠语义，不覆盖配置的截断长度，因此已进入持久化投影缓存的行会保留原有截断，直到其会话被重新折叠。
- **截断以 UTF-16 码元计数** —— 截断点可能落在一个字素簇内部，因此消费者应将保留文本渲染为预览，而不应视其为完整句子。
- **结局描述的是轮次而非任务** —— 模型报告自己无法完成、但轮次以 `completed` 结束时，仍报告 `completed`；折叠分类的是生命周期，而非底层工作是否成功。
